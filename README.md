# Мехай · Механик с AI

Рабочее место механика автопарка. Все начальные машины, показания, дефекты и заявки — демонстрационные, не данные реального перевозчика.

## Запуск

Node.js 24+.

```sh
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3087. Для разработки отдельно `npm run server` и `npm run dev` (http://127.0.0.1:5173). API и фотографии проксируются на 3087.

SQLite и фотографии сохраняются в `data/`, папка исключена из Git. Для резервной копии остановить приложение и скопировать всю папку. Удаление папки приводит к потере пользовательских данных.

## Диагностика НейроДВС и заявка на дефектовку

Данные НейроДВС и сервисы Mock ML/ТОиР поставляются организатором отдельно и загружаются приватно при развёртывании. URL источника и исходный архив не входят в Git или Docker-образы. Загрузчик требует HTTPS и доверенный SHA-256 архива из защищённой конфигурации хоста. Локально задайте `NEURODVS_DATA_PATH` и `MEHAY_KB_DIR`, чтобы использовать подготовленные материалы. Автоматические проверки используют собственный синтетический набор данных.

Для локального запуска двух тестовых сервисов получите приватную копию mock-пакета и установите его зависимости:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r /path/to/private-neurodvs/requirements.txt
```

Запустите каждый сервис в отдельном терминале из корня проекта:

```sh
.venv/bin/uvicorn --app-dir /path/to/private-neurodvs mock_ml.app:app --port 8001
.venv/bin/uvicorn --app-dir /path/to/private-neurodvs mock_toir.app:app --port 8002
```

Для просмотра страниц руководства внутри чата локальному серверу нужна утилита `pdftoppm`. На macOS её устанавливает `brew install poppler`, на Debian и Ubuntu — пакет `poppler-utils`. Образ Docker уже включает эту утилиту.

Адреса сервисов для Мехая задаются через `MOCK_ML_URL` и `MOCK_TOIR_URL` в `.env`. Откройте НейроДВС, выберите машину и проверку. При отклонении откройте страницу руководства, проверьте предложенные работы и отправьте заявку. Номер возвращает Mock ТОиР. Заглушка хранит полученные заявки в памяти процесса. При сбое записи выберите новую сессию после повторного замера. Прототип просит повторить замер при confidence ниже 0,55 или качестве сигнала хуже good. Для заявки используется демонстрационная шкала anomaly_score: ниже 0,65 — низкий приоритет, от 0,65 — средний, от 0,85 — высокий. Это параметры прототипа, эксплуатационную валидацию шкалы заказчик не предоставлял.

Для отдельной демонстрации задайте новый путь в `MECHANIC_DB`. Демо-записи о ремонте формируются воспроизводимо для приватно загруженного парка.

Диагностика, выдержки для заявки и отправка в ТОиР работают локально. Для ответа на свободный вопрос модель OpenRouter выбирает строки из найденных страниц. Мехай показывает оригинальный текст этих строк, номер страницы и ссылку на PDF. Для свободного вопроса на английском, хинди, таджикском или узбекском сервис переводит вопрос для поиска по русским руководствам и показывает перевод найденной выдержки вместе с оригиналом и страницей. При переводе числовые значения сверяются с оригиналом. Запросы к OpenRouter оплачиваются по тарифу провайдера. Если ключ не задан, ручной поиск по документам доступен в общем помощнике.

В разделе «Состояние парка» главный механик видит три группы по последнему замеру и очередь машин для проверки. Нажатие на машину открывает её замеры за последние 3–5 сессий, сохранённые заключения и номера заявок ТОиР. Неудачный замер остаётся в истории с пропуском оценки. Карантин в демонстрационной очереди соответствует качественному замеру с отклонением, уверенностью от 0,55 и оценкой аномалии от 0,85.

При настроенном `OPENROUTER_API_KEY` помощник выбирает по свободной просьбе инструмент диагностики, руководств, истории или подготовки заявки. При недоступности провайдера доступны кнопки действий. Для отправки в ТОиР нужны операция и страница руководства для выбранного двигателя. Если такого основания нет, Мехай сообщает, что нужна дефектовка.

## Помощник

Скопировать `.env.example` в локальный `.env`, установить серверный `OPENROUTER_API_KEY`, затем запустить:

```sh
node --env-file=.env server/index.mjs
```

Модель по умолчанию — `openai/gpt-5.4-mini`, задаётся через `OPENROUTER_MODEL`. Локальный поиск по руководствам работает без ключа. Ключ нужен для внешней модели и интернет-поиска. Ключ не отправляется в браузер и не хранится в SQLite. Ошибка внешнего сервиса не подменяется демонстрационным ответом.

Опция поиска в открытых источниках использует web plugin OpenRouter (отдельная тарификация провайдера). Ссылки ответа берутся из возвращённых API аннотаций. Поиск по каталогу на странице источников фильтрует заголовки/описания, а не содержимое всех сайтов. Форумы не являются заводским нормативом; соответствие модели двигателя и комплектации требует проверки. Загруженные фотографии хранятся для осмотра, автоматический анализ фотографий пока не выполняется.

### Поиск по руководствам

Откройте помощника, выберите двигатель и включите «Искать только по руководству». При подключённой базе ответ ссылается на страницу исходного PDF. Поиск в интернете включается отдельно. Внешнему поисковому сервису передаются публичный запрос и модель двигателя.

PDF, постраничный индекс и подготовленные по руководствам планы с переводами хранятся у оператора в каталоге с ограниченным доступом за пределами рабочей копии Git. Укажите абсолютный путь через `MEHAY_KB_DIR`. Структура каталога:

```text
pdf/           # оригиналы, доступные оператору
index.json     # индекс тех же файлов
guidance.json  # дополнительные проверенные планы с привязкой к странице
```

На рабочей станции задайте `MEHAY_KB_DIR` в локальном окружении сервера. Индекс для поддерживаемых руководств строит `python3 scripts/index-manuals.py` с этой же переменной; нужны PyMuPDF, Tesseract и языковые пакеты русского и английского. На стенде оператор размещает комплект в `/opt/mehay/knowledge`; контейнер читает его через `/knowledge`. Ограничьте доступ к каталогу учётной записью сервиса. Руководства и извлечённые тексты исключены из поставки приложения. Без внешней базы доступны рабочее место и диагностические статусы. Для репозиторных тестов используются самостоятельно написанные учебные данные.

## Что входит

- Реестр демонстрационного автопарка, карточка машины, цвет, фотографии моделей, поиск и состояния.
- Сырая OBD-телеметрия и ML-событие отдельно, расхождения показаний пробега, импорт телеметрии через JSON.
- История обслуживания и замен деталей по дате/пробегу.
- Чек-лист с черновиком/завершением, замечания, фотографии и постоянные заметки.
- Заявки на ремонт, подбор и закупку; изменение статуса и история завершенного ремонта.
- Серверный помощник OpenRouter с контекстом выбранной машины и опциональным веб-поиском.

## Проверочный сценарий второй версии

Работа строится вокруг выбранной машины. В реестре выбирайте номер и фото модели; внутри карточки доступны осмотр, детали, заявки, заметки и помощник. Данные сценариев добавляются один раз, существующие записи не очищаются.

1. Открыть ГАЗель Next: сравнить ручной и OBD-пробег, посмотреть ошибку ЭБУ и предварительную ML-оценку.
2. В осмотре отметить результат и комментарий. Добавить заметку «Повреждение» либо «Нужна мойка»; после устранения закрыть замечание отдельно от ремонта.
3. Найти деталь в тестовом каталоге, собрать комплект и отметить «Есть / Нет / Не проверено». Перенести комплект в заявку подбора или закупки. Указанное наличие и применимость демонстрационные.
4. При редактировании заявки спросить помощника: «Есть ли уже похожие открытые заявки по этой машине? Что стоит уточнить перед закупкой?» Чат передаёт черновик как черновик, а сохранённые заявки загружает сервер. Помощник не выполняет покупки и не завершает работы.
5. Отметить выполненные операции и фактически использованное количество деталей. Статус всей заявки сам по себе не означает выполнение каждой строки.
6. Открыть отчёт: проверить диагностику, выполненные и оставшиеся работы. Распечатать или сохранить PDF средствами браузера; скачать JSON этого же снимка для передачи в другую систему.

Отчёт имеет `schemaVersion` и `generatedAt`; печать и JSON используют один загруженный снимок. Это выгрузка данных, не подтверждение доставки в ERP и не подписанный акт. История чата относится к машине и текущей браузерной сессии; официальный результат фиксируйте в заявке/осмотре.

Мобильный вариант — адаптивное веб-приложение. `127.0.0.1` телефона указывает на сам телефон; для общего доступа нужен сервер с HTTPS и входом, как описано ниже. Офлайн-синхронизация пока не реализована.

Закупочные заявки остаются внутри приложения: внешние заказы и платежи не выполняются. Наличие детали на складе и совместимость по VIN не подтверждаются. Реальные коннекторы OBD, ML и учётной системы требуют контрактов/доступов; текущие интеграции обозначены как демонстрационные. Показание OBD одометра может отсутствовать — это зависит от машины/адаптера.

## Размещение и учётные записи

Приложение работает отдельным сервисом под `/mehay/`: лендинг `/mehay/`, вход `/mehay/login`, рабочее место `/mehay/app`. Контейнер доступен только через loopback-порт и HTTPS reverse proxy. Каноническая доставка описана в `.github/workflows/ci.yml`, конфигурация — в `deploy/compose.yaml`. Индексация раздела выключена; общий sitemap KartRacers не меняется.

Первого администратора создают в интерактивном терминале контейнера:

```sh
docker exec -it mehay node server/index.mjs --create-admin
```

Команда запрашивает данные локально; стандартного пароля нет. Первоначальная настройка через публичный HTTP-прокси закрыта. Администратор создаёт пользователей, меняет роли, отключает учётные записи и сбрасывает пароли. Отключение и смена пароля отзывают сессии. API и вложения требуют входа; cookie ограничена путём приложения. Это один общий парк для всех его механиков, без разделения организаций.

Публикация требует отдельного секрета GitHub Actions `VPS_SSH_KEY`, доступного GHCR-образа по digest и постоянного каталога данных. Секреты хранятся вне репозитория. Перед обновлением нужен согласованный способ резервного копирования SQLite и вложений; инструкция выше описывает копирование при остановленном сервисе.

## Основа и примеры

Спецификация и API: [docs/brief.md](docs/brief.md).

Рабочее место использует Bootstrap 5. Стили входят в локальную сборку, а кириллица набирается системным шрифтом устройства. Крупные кнопки рассчитаны на работу с телефона и планшета в мастерской.

Рассмотрены [LubeLogger](https://github.com/cpayton0/lubelogger) (MIT, журнал обслуживания) и [Fleetbase](https://github.com/fleetbase/fleetbase) (AGPL/commercial, процессы автопарка). Код этих проектов не включён.

Фотографии моделей из Wikimedia Commons служат иллюстрациями; год и комплектация могут отличаться от демонстрационных записей. [Авторы и лицензии](docs/photo-credits.md). Загруженные механиком фотографии осмотра показываются отдельно.

### Стоимость демонстрационного сценария

Контрольный прогон 26 ноября 2026 года через OpenRouter дал $0,00019650 за маршрутизацию диагностики, $0,00022275 за выбор инструмента для вопроса, $0,00346125 за подготовку ответа по найденным страницам и $0,00021300 за маршрутизацию заявки. Один замер, один вопрос и одна заявка в этом прогоне стоили $0,00409350. Сам поиск по локальному индексу выполняется на сервере.

При 50 машинах и 26 таких сессиях в год на машину, с двумя вопросами за сессию, расход на модель составит около $10,11 в год, с тремя — $14,90. Формула в долларах: число сессий × (0,00019650 + число вопросов × 0,00368400 + 0,00021300). Это экстраполяция одного измеренного прогона. Длина вопросов, модель, повторы запросов и изменение тарифа влияют на результат. Для полной стоимости эксплуатации парку нужно добавить собственные расходы на сервер, хранение PDF, индексацию/OCR и поддержку.
